01 / 진단

지금 무엇이 문제인가

CSS 3개 파일(globals 537줄 · admin 329줄 · login 62줄)을 전수 조사한 실측이다. Tailwind 유틸리티는 단 한 곳도 쓰이지 않아 tailwind.config.js 의 색 토큰은 죽은 설정이다.

타입 램프가 없다

21 종의 font-size 가 11 · 11.5 · 12 · 12.5 · 13 · 13.5 · 14 · 14.5 · 15 · 15.5 · 16 · 16.5 · 17 · 17.5 · 18 · 18.5 · 19 · 20 · 22 · 23 · 24px 로 0.5px 단위까지 흩어져 있다. 0.5px 차이는 사람이 구분하지 못하므로 위계가 아니라 잡음이다.

모서리·그림자에 위계가 없다

20 종 radius — --radius:16px 를 선언해두고 실제로는 7·8·9·10·12·16·18·999px 를 하드코딩했다. 그림자는 15 종이고 전부 음수 spread 를 쓴 각자 다른 레시피다.

상태가 hover 하나뿐이다

:focus-visible 0건 · :active 0건 · :disabled 0건. 버튼·대메뉴·페이저·탭·캐러셀 도트를 키보드로 이동하면 어디에 있는지 보이지 않는다 (WCAG 2.4.7 위반).

02 / 기반

단청 램프 — 색은 그대로, 계단만 생긴다

Fluent brandWeb(#0f6cbd 기준 16단)의 OKLCH 명도차·채도비 곡선을 그대로 떼어내 석간주·뇌록·금의 색상각에 적용했다. 80 단계는 현재 쓰는 색과 정확히 같은 hex 이고, 나머지 단계가 hover·pressed·틴트·테두리를 공급한다. 흰 테두리로 표시한 칸이 앵커다.

중성 Fluent 중성 램프를 한지 색상각(H 84.6°)으로 이식

Fluent 의 무채색 회색(#ffffff → #e6e6e6, #242424 → #707070) 계단을 한지 톤으로 옮겼다. 현재 손으로 박아둔 #f6efe3(표 헤더) · #f0ece3(배지) · #fcf9f3(캘린더 셀) 이 모두 이 램프의 특정 단계와 OKLCH 거리 0.018 이내로 일치한다 — 거의 같은 색인데 이름이 없었을 뿐이다.

타입 램프

05 / 상태

6상태 규약 — 지금은 두 칸만 채워져 있다

Fluent 2 는 모든 상호작용 요소가 rest · hover · pressed · selected · disabled · focus 를 갖도록 규정한다. 현재 상태를 전수 조사한 결과다.

요소resthoverpressedselecteddisabledfocus

포커스가 특히 문제다. 현재 입력 필드만 outline:2px solid var(--accent); outline-offset:1px 을 갖는데, 이것도 :focus 라서 마우스 클릭에도 뜨고(:focus-visible 이 아니다), 석간주 단색이라 흰 서피스와 한지 배경 중 한쪽에서 대비가 약해진다. Fluent 2 방식은 밝은 안쪽 선 + 어두운 바깥쪽 선 2겹이라 어느 배경에서도 보인다.

06 / 접근성

명도 대비 실측 — 현재 5건 위반

WCAG 2.1 공식(상대휘도 → 대비비)으로 실제 계산했다. 본문 4.5:1, 비텍스트 UI 요소 3:1 기준.

조합전경배경대비기준판정단청 유지 수정안

입력 필드 경계선 — 새로 드러난 위반

현재 모든 입력이 border:1px solid var(--line) = #E7DECF 를 쓴다. 한지 배경 위 대비가 1.20:1 이다. WCAG 1.4.11 은 컨트롤의 경계선에 3:1 을 요구한다 — 장식용 구분선은 면제지만 입력 필드 테두리는 그 컨트롤을 식별하는 요소라 면제 대상이 아니다.

Fluent 2 는 이걸 위해 colorNeutralStrokeAccessible (#616161, 6.19:1) 을 별도로 둔다. 한지판은 #63615d — 대비 6.18:1.

제 임계값 오류를 밝혀둔다

처음 검증에서 Stroke1/Stroke2/비활성 전경을 3:1 로 걸어 “실패”로 판정했는데 기준을 잘못 적용한 것이다. Fluent 자신의 colorNeutralStroke1 #d1d1d1 도 흰 배경 대비 1.53 이고, WCAG 1.4.11 은 장식용 구분선을, 1.4.3 은 비활성 컨트롤을 명시적으로 면제한다. 장식선 1.5:1 은 결함이 아니다. 진짜 조치 항목은 위의 입력 경계선 하나다.

07 / 확정

확정된 방향

2026-07-30 승인. 아래 값이 시안의 AFTER 기본값으로 고정되어 있다. 컨트롤바의 노브는 남겨 두었으니 다른 단계와 계속 비교해 볼 수 있다.

1 · 카드 모서리확정 12px · 2XLarge

4px 은 업무 도구처럼 단단하고, 16px 은 지금의 부드러움을 유지한다. 둘 다 Fluent 램프 안이다.

현재 16px 에서 한 단계만 조여 산사의 부드러움을 남기면서 Fluent 위계(입력 4 < 카드 12 < 드롭다운 8)를 만든다. 4px 은 사찰 홈페이지에 너무 사무적이라 채택하지 않았다.

2 · 본문 크기확정 16px / 행간 26px

현재 사이트는 18px / line-height 1.8(= 32px) 이다. Fluent 기본 본문 14px/20px 은 한글에 작다.

Base400 단계를 쓰고 행간만 한글용으로 22 → 26px 보정한다. 현재 18px 에서 2px 줄어드는 변화이므로, 실제 화면에 얹은 뒤 본문 밀도를 한 번 더 확인한다. 답답하면 Base500(20px/32px)로 한 단계 올리는 것이 대안이다 — 램프 안이라 토큰 한 줄만 바꾸면 된다.

3 · 엘리베이션확정 rest 2 · hover 4 · 드롭다운 16

현재 그림자는 음수 spread 로 아주 옅게 깔려 있어 실효 부양은 shadow2~4 사이다.

지금의 은은함을 유지하는 값이다. 그림자 색은 먹 계열 rgba(35,33,30,·) 로 유지해 검정 그림자의 차가움을 피한다.

4 · 위험색 분리확정 신설 #af1937

삭제 버튼을 석간주에서 떼어내면 단청 팔레트에 없던 색이 하나 들어온다.

되돌릴 수 없는 동작이 브랜드색과 같으면 실수를 유발한다. 석간주에서 색상각 12° 를 틀고 채도를 1.35배 올려 분리했다. 흰 글씨 대비 6.96:1 로 AA 통과.

5 · 적용 순서확정 병행 이전

공통 토큰 → 공개 페이지 → 관리자/폼. 한 번에 갈지 나눠 갈지.

토큰 레이어를 먼저 넣고 기존 값과 병행시킨다 — --line 을 --n-stroke-2 의 별칭으로 두는 방식. 그러면 화면별로 하나씩 옮기면서 언제든 Ver1.1 로 되돌릴 수 있고, 중간 상태에서도 사이트가 깨지지 않는다.

이 시안 자체는 코드베이스를 수정하지 않는다 — 독립 페이지이고, BEFORE 쪽은 현재 CSS 값을 그대로 옮긴 것이라 비교가 공정하다. 롤백 기준점은 Ver1.1 태그(67a2ba0)이고, 구현은 그 지점에서 갈라진 브랜치에서 진행한다.

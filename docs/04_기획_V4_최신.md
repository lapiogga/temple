# 포교사찰 홈페이지 구축 기획 V4

> 구축 방식: 바이브코딩 자체 개발 · **AWS 자체 호스팅 + 별도 도메인 + 자체 PostgreSQL**
> 단계 분리: **1차(공개 홍보·중창기·소식, ~2026.08말) / 2차(신도 회원·커뮤니티, ~2026.11말)**
> V4 변경: **디자인 셋(폰트·컬러·타이포) 확정 + 디자인 자산 확보 계획 + 수집 체크리스트(부록 A) 추가**

---

## 0. V2 → V3 변경 요약

| 구분 | V2 | V3 (변경) |
|------|-----|-----------|
| 인프라 | Supabase/Vercel(국외) 권장 | **현재 사용 중인 AWS 자체 호스팅** |
| 도메인 | 미정 | **별도 도메인 신규(Route 53)** |
| DB | Supabase(관리형) | **자체 PostgreSQL(직접 설치·운영)** |
| 개인정보 국외이전 | 결정 필요(리스크) | **AWS 서울 리전 사용 시 해소** |
| 단계 | MVP/Phase2(기능 기준) | **1차=공개 정보, 2차=회원·커뮤니티(명확 분리)** |
| 1차 범위 | 회원·게시판 포함 | **회원·커뮤니티 제외 → 일정 리스크 대폭 감소** |

> **핵심 효과**: 가장 복잡하고 보안 민감한 영역(회원 인증·권한 혼용·커뮤니티)을 2차로 분리함으로써, 1차는 **인증이 거의 필요 없는 공개 사이트 + 운영자 관리화면**만으로 구성됩니다. 8월말 일정이 안정권에 들어옵니다.

## 1. 단계별 범위 정의

### 1차 (~2026년 8월말) — 공개 홍보·소식 사이트
인증 부담 최소화. **일반 방문자는 로그인 없이 모두 열람**, 운영자만 콘텐츠 등록.

| 영역 | 1차 포함 기능 |
|------|------|
| 사찰 소개 | 인사말, 연혁, 가람배치·전각, **가람 중창기**, 스님 소개, 오시는 길 |
| 법회·행사 | 정기 법회 안내, 행사 캘린더(공개) |
| 소식 | 공지사항, **사찰 소식**(주력), 메인 배너 노출 |
| 갤러리 | 행사·사찰 사진 앨범(공개) |
| 법문 | (선택·경량) 공개 법문 글/영상 임베드 |
| 후원 | **계좌 안내** 페이지(결제 미연동) |
| 관리 | **운영자 전용 관리화면** + 운영자 로그인(소수 계정) |

> 1차의 인증은 **운영자 로그인뿐**입니다. 신도 회원 가입 체계는 없습니다. → 개인정보 수집이 사실상 없어 컴플라이언스 부담이 매우 낮습니다.

### 2차 (~2026년 11월말) — 신도 회원·커뮤니티
| 영역 | 2차 추가 기능 |
|------|------|
| 회원 | 신도 회원 가입·**운영자 승인제**·로그인, 마이페이지 |
| 권한 | 공개/회원 **혼용 권한 체계** 적용 |
| 커뮤니티 | 자유게시판, 신행수기, 묻고답하기(Q&A), 댓글 |
| 회원 전용 | 회원 소식·자료실, 회원 전용 갤러리·법문 |
| 부가 | 통합 검색, 알림(메일/문자 등), 법문 아카이브 고도화 |
| 컴플라이언스 | 개인정보처리방침·수집 동의(회원 도입 시점) |

`[1]`=1차 / `[2]`=2차 / `(회)`=회원 전용

```
홈 [1]
├─ 사찰 소개 [1]
│   ├─ 인사말 / 연혁 / 가람배치·전각
│   ├─ ★ 가람 중창기                      [1]
│   ├─ 스님 소개 / 오시는 길
├─ 법회 · 행사 [1]
│   ├─ 정기 법회 안내 / 행사 캘린더
├─ 소식 [1]
│   ├─ 공지사항 / ★ 사찰 소식 / 갤러리
├─ 불교 콘텐츠
│   ├─ 법문(공개, 경량)                    [1]
│   └─ 법문 아카이브 고도화 · 회원분(회)    [2]
├─ 후원 안내(계좌) [1]
├─ 커뮤니티                                 [2]
│   ├─ 자유게시판(회) / 신행수기 / Q&A(회)
├─ 로그인 · 마이페이지                       [2, 회]
└─ [관리자] 운영자 콘텐츠·(2차)회원 관리      [1~]
```

### '가람 중창기' 설계 (1차 핵심 콘텐츠)
- **연대기형 스토리 콘텐츠**: 시기 → 중창 내용 → 전/현재 사진 → 비고
- 표현: 세로 타임라인 + 사진. 대외 홍보 가치가 높은 1차 대표 콘텐츠로 비중 있게 디자인.
- 데이터: `(시기, 제목, 본문, 사진 다중, 정렬순서)` 별도 콘텐츠 타입.

## 3. AWS 아키텍처 (자체 호스팅 · 자체 PostgreSQL)

현재 사용 중인 AWS 환경을 활용합니다. 운영 사이트는 개발 인스턴스와 **분리**하는 것을 권장합니다.

```
[방문자]
   │  HTTPS
   ▼
Route 53 (별도 도메인)  ──►  EC2 (Nginx, 443/80)
                                  │  reverse proxy
                                  ▼
                             Next.js 앱 (Node, systemd/PM2)
                                  │
                                  ▼
                             PostgreSQL (자체 설치, localhost 전용)
이미지/첨부 → S3(권장) 또는 EC2 로컬 디스크
TLS → Let's Encrypt(certbot) 또는 ACM
백업 → pg_dump → S3 (cron) + EBS 스냅샷
```

### 구성 요소
| 레이어 | 선택 | 메모 |
|--------|------|------|
| 앱 프레임워크 | **Next.js (App Router)** | 바이브코딩 적합, 1차→2차 확장 용이 |
| UI | Tailwind CSS (+ 컴포넌트 라이브러리) | 빠른 반응형 |
| 런타임 | Node + **PM2 또는 systemd** | 프로세스 상시 구동·자동 재시작 |
| 웹서버 | **Nginx** 리버스 프록시 | 443 종단, 정적 캐싱 |
| DB | **PostgreSQL 자체 설치** | 외부 포트 비공개(localhost), 앱에서만 접근 |
| ORM | Prisma 또는 Drizzle | 스키마·마이그레이션 관리 |
| 미디어 | **S3 권장**(또는 EC2 로컬) | 사진 내구성·백업 유리 |
| DNS/도메인 | **Route 53** | 별도 도메인 등록·연결 |
| TLS | Let's Encrypt(certbot) | 자동 갱신 cron |

### 운영(Ops) 체크
- **EC2 보안그룹**: 80/443 공개, SSH(22)는 본인 IP 제한, **PostgreSQL 포트(5432) 외부 차단**(localhost만 허용).
- **백업**: `pg_dump` 일 1회 → S3 업로드 cron, EBS 스냅샷 주기 설정.
- **서울 리전(ap-northeast-2)** 사용 시 데이터 국내 보관 → 2차 회원 개인정보 **국외이전 이슈 없음**.
- **배포**: 깃 기반 + 빌드 후 PM2 reload. (CI 자동화는 선택)
- 운영/개발 인스턴스 분리, 또는 동일 인스턴스 사용 시 포트·디렉터리 격리.

> 자체 Postgres는 관리형(RDS) 대비 운영 부담(백업·패치·모니터링)이 직접 책임입니다. 소규모라 부담은 작지만, **백업 cron과 보안그룹만큼은 1차 셋업 단계에서 반드시 검증**하세요.

## 5. 보안 · 개인정보 · 운영

- **1차**: 회원 개인정보 수집 없음(운영자 계정만). 컴플라이언스 부담 최소.
- **2차**: 회원 도입 시 개인정보처리방침·최소 수집·수집 동의 필수. 서울 리전이면 국외이전 불필요.
- **권한(2차)**: 프론트 메뉴 숨김만으로 불충분 → **서버 API·DB 레벨에서 권한 강제**, 회원 데이터의 비회원 노출 테스트 필수.
- **운영 지속성**: 비전문가 운영 전제 → 관리화면을 단순하게, **콘텐츠 등록 매뉴얼** 산출물 포함.
- **공통 보안**: 운영자 비밀번호 해시·세션 관리, 업로드 파일 검증, 백업·스냅샷, certbot 자동 갱신.

## 6. 디자인 방향 및 자산 확보

### 6-1. 디자인 톤
- 단아·정갈, 여백 중심(전통+현대 균형), 한지/먹색 베이스 + 단청 추출 포인트
- **모바일 우선**, 큰 글씨·큰 터치 영역(중·장년 신도 배려)
- 메인 최상단에 **사찰 소식 + 법회 일정**이 즉시 보이도록(1차 주력)

### 6-2. 디자인 셋 — 타이포그래피
오픈 라이선스 폰트만 사용해 라이선스 부담을 없앱니다.

| 용도 | 폰트 | 라이선스 | 비고 |
|------|------|------|------|
| 본문·UI | **Pretendard** | SIL OFL(오픈) | 가독성·다양한 굵기, 기본 |
| 제목·강조(선택) | **본명조(Noto Serif KR) / 마루 부리** | 오픈 | 사찰 정서의 명조 포인트 |
| 숫자·라틴(선택) | Pretendard 내장 | — | 별도 폰트 불필요 |

**타입 스케일(모바일 우선, 고령 신도 배려로 본문 17px 기준)**

| 구분 | 크기 / 행간 | 굵기 |
|------|------|------|
| H1 (페이지 제목) | 30–34px / 1.3 | 700 |
| H2 (섹션) | 24–26px / 1.35 | 700 |
| H3 (소제목) | 20px / 1.4 | 600 |
| 본문 | **17px / 1.7** | 400 |
| 보조·캡션 | 14px / 1.6 | 400 |

> 본문 행간을 넉넉히(1.7) 두는 것이 중·장년 가독성에 효과적입니다.

### 6-3. 디자인 셋 — 컬러 팔레트 (단청·한지 기반)
오방색·단청에서 추출한 절제된 팔레트입니다. 포인트색은 1~2개로 한정해 정갈함을 유지합니다.

| 토큰 | HEX | 용도 |
|------|------|------|
| `ink` (먹) | `#23211E` | 본문 텍스트 |
| `ink-soft` (먹 보조) | `#6B6258` | 보조 텍스트·캡션 |
| `hanji` (한지 배경) | `#FAF6EE` | 페이지 배경 |
| `surface` | `#FFFFFF` | 카드·콘텐츠 면 |
| `line` (구분선) | `#E7DECF` | 경계·테두리 |
| `dancheong-red` (석간주, 주 포인트) | `#9E3B2F` | CTA·강조·링크 |
| `dancheong-teal` (뇌록, 보조 포인트) | `#2E7D74` | 보조 강조·태그 |
| `gold` (금·황, 장식선) | `#C8A24B` | 구분선 장식·아이콘 포인트 |

**바이브코딩용 CSS 변수(붙여넣기용)**
```css
:root{
  --color-ink:#23211E; --color-ink-soft:#6B6258;
  --color-hanji:#FAF6EE; --color-surface:#FFFFFF; --color-line:#E7DECF;
  --color-accent:#9E3B2F;      /* 석간주 - 주 포인트 */
  --color-accent-2:#2E7D74;    /* 뇌록 - 보조 */
  --color-gold:#C8A24B;        /* 금/황 - 장식 */
  --font-body:'Pretendard',system-ui,sans-serif;
  --font-title:'Noto Serif KR',serif;
  --text-base:17px; --leading-body:1.7; --radius:12px;
}
```
> 접근성: 본문(`ink`)과 배경(`hanji`) 명도대비는 충분(4.5:1 이상). 포인트색 위 흰 글씨도 대비 확보. 색만으로 정보를 구분하지 말 것(아이콘·텍스트 병기).

- **문화포털 전통문양** (culture.go.kr): 한국문화정보원 공공 개방, 단청·연꽃·테두리 원형 소스. 공공누리로 출처표시 시 변형·상업 이용 가능.
- **공유마당** (gongu.copyright.or.kr): 한국저작권위원회, 항목별 CC 라이선스(예: CC BY). **항목마다 저작권자·이용조건 확인** 필수.
- **공공누리** (kogl.or.kr): 공공저작물. **유형(제1~4)**에 따라 상업·변형 제한이 있으니 가급적 제1유형(출처표시) 선택.
- (보완) Freepik·Pngtree: 무료 등급은 출처표시·사용 제한, AI 생성물 다수 → 국내 공공 소스 우선, 부족 시 보완.

### 6-6. SVG 자산 시스템 (바이브코딩 적합)
- 문양·아이콘·도식을 **재사용 SVG 컴포넌트 세트**로 구성 → 라이선스 무부담·일관성·다해상도 대응.
- 반복 문양은 단위 문양을 SVG `pattern`으로 정의해 배경 타일링(용량 절감).
- 가람배치도·중창기 연표는 외부 이미지 대신 SVG 커스텀(수정·확장 용이).

### 6-7. AI 생성 가이드라인
- **허용**: 추상 배경, 한지 질감, 장식 패턴 등 비종교적·장식 요소.
- **지양**: 불상·진언·특정 문화재 재현(정확성·존엄성·저작권 문제). 성보는 실사 사용.

### 6-8. 라이선스 관리 원칙
- 모든 외부 자산은 **출처·라이선스·이용조건을 수집 시점에 기록**(부록 A 체크리스트 활용).
- 출처 불명·권리관계 불확실 자산은 **사용 금지**.
- 폰트·아이콘·문양·사진별 라이선스 근거를 한 곳(자산 대장)에 보관.

# 포교사찰 홈페이지 구축 기획 (초안)

> 자료 조사 + 기획 골격 / 작성 단계: 사전 기획(Pre-Planning)
> 사업 성격: 자체 발주 · 상용/오픈소스 CMS 기반 · 정보 제공 + 커뮤니티 중심

---

## 1. 프로젝트 개요

| 항목 | 내용 |
|------|------|
| 대상 | 지역 신도 중심의 일반 포교사찰 |
| 사업 성격 | 자체 발주 (KWCAG·전자정부 표준프레임워크 등 법적 의무 대상 아님) |
| 핵심 목표 | ① 사찰 소개 및 법회/행사 안내 ② 불교 콘텐츠·커뮤니티(법문·게시판) |
| 부차 목표 | 신도 결속 강화, 신규 방문자 접근성 확보, 모바일 중심 접근 |
| 결제·예약 | 미포함 (후원은 '안내' 수준, 온라인 결제 미적용) |

### 기획 방향성 요약
포교사찰 사이트는 관공서·기업 사이트와 달리 **정보 전달 + 정서적·종교적 분위기 + 신도 커뮤니티**가 함께 작동해야 합니다. 이번 사업은 매출형(예약·결제)이 아니라 **신행(信行) 지원형**이므로, "법회·행사를 놓치지 않게 하고, 법문을 꾸준히 접하게 하고, 신도가 모이는 공간"이 되는 것이 성공 기준입니다.

## 2. 타깃 사용자 및 핵심 니즈

| 사용자 | 특성 | 핵심 니즈 |
|--------|------|-----------|
| 기존 신도 (주 사용자) | 중·장년층 비중 높음, 모바일 사용 | 법회 일정, 공지, 사진/소식, 게시판 |
| 신규 방문/예비 신도 | 검색 유입 | 사찰 소개, 오시는 길, 입문 안내 |
| 사찰 운영진 | 비전문가(스님/총무) | **쉬운 콘텐츠 등록·관리** |

> **시사점**: 주 사용자층 연령을 고려하면 ① 큰 글씨·단순 내비게이션 ② 모바일 우선 ③ 운영자가 코딩 없이 게시물을 올릴 수 있는 관리도구가 필수입니다. 법적 의무는 없더라도 **고령 신도를 위한 가독성·접근성**은 KWCAG 일부 원칙(명도대비, 글자 확대, 키보드 접근)을 자발적으로 반영하는 것을 권장합니다.

## 3. 정보구조 (IA) / 메뉴구조도

3 Depth 이내, GNB 6개 내외로 단순하게 구성합니다.

```
홈
├─ 사찰 소개
│   ├─ 인사말 (주지스님)
│   ├─ 연혁
│   ├─ 가람 배치 · 전각 안내
│   ├─ 스님 소개
│   └─ 오시는 길 (지도·교통)
├─ 법회 · 행사
│   ├─ 정기 법회 안내 (요일·시간)
│   ├─ 행사 캘린더 (월간)
│   ├─ 연중 불교 행사 (초파일·동지 등)
│   └─ 신청·문의 (선택)
├─ 불교 콘텐츠
│   ├─ 법문 (글 / 음성 / 영상 아카이브)
│   ├─ 경전 · 교리 안내
│   ├─ 불교 입문 · 예절
│   └─ 추천 자료 · 링크
├─ 소식 · 커뮤니티
│   ├─ 공지사항
│   ├─ 사찰 소식
│   ├─ 갤러리 (사진·영상)
│   ├─ 자유게시판
│   ├─ 신행수기 · 방명록
│   └─ 묻고 답하기 (Q&A)
└─ 후원 안내
    └─ 후원 안내 · 계좌 정보 (결제 미연동)

[공통] 사이트맵 · 개인정보처리방침 · 모바일 햄버거 메뉴
```

- 모바일 자동 반응형
- 정기 백업 · 보안 업데이트 체계

## 5. 콘텐츠 전략
- **법문 아카이브**: 텍스트 부담을 줄이기 위해 음성·영상은 YouTube/팟캐스트에 올리고 사이트에 임베드 → 운영 부담↓, 검색 노출↑
- **법회·행사**: 캘린더를 단일 진실원천(Single Source)으로 두고 메인·공지에 자동 연동
- **저작권 주의**: 경전·법문·찬불가 가사, 외부 사진/영상은 출처·이용허락 확인 필수 (특히 음원·이미지)
- **꾸준한 운영 가능성**이 콘텐츠 양보다 중요 → 등록 쉬운 구조로 설계

## 6. 구축 방식 / CMS 비교 (자체 발주 기준)

정보 + **게시판/커뮤니티**가 핵심이므로, 이 요건을 중심으로 비교했습니다.

| 플랫폼 | 유형 | 게시판·커뮤니티 | 콘텐츠/확장 | 운영 난이도 | 비용 구조 | 적합도 |
|--------|------|:---:|:---:|:---:|------|:---:|
| **그누보드 / 라이믹스** | 설치형(오픈소스) | ◎ 국내 표준, 매우 강함 | ○ | △ 초기 셋업·테마 필요 | 무료, 호스팅·제작비 | ★★★ |
| **워드프레스** | 설치형(오픈소스) | △ 한국형 게시판 약함(플러그인 의존) | ◎ 법문·블로그·확장 | △ 보안 관리 필요 | 무료, 호스팅·테마 | ★★ |
| **아임웹** | 빌더(SaaS) | △ 제한적 | ○ | ◎ 노코딩, 매우 쉬움 | 월 구독(연 24만 원대) | ★★ |
| 카페24 | 빌더(SaaS) | △ | △ 쇼핑몰 특화 | ○ | 엔진 무료+수수료 | ✕ |
| Wix | 빌더(해외) | △ | ○ | ○ | 월 구독 | ✕ |

### 권고안
- **1안 (균형형, 추천)**: **그누보드/라이믹스 + 사찰형 테마**
  국내 커뮤니티·게시판 표준으로 신도 게시판·회원·갤러리에 가장 강하고, 유지보수 가능한 외주 인력 풀이 넓습니다. 디자인은 테마 커스터마이징으로 해결.
- **2안 (콘텐츠 강조형)**: **워드프레스**
  법문 아카이브·블로그·SEO에 강점. 단, 한국형 게시판은 별도 플러그인·세팅이 필요하고 보안 관리 부담이 있음.
- **3안 (운영 편의 최우선)**: **아임웹**
  운영진이 IT에 약하고 빠른 오픈이 목표라면. 단 커뮤니티/게시판이 약해, 활발한 신도 게시판이 핵심이면 부적합.

> 의사결정 기준: **"신도 게시판이 얼마나 활발할 것인가"** 와 **"운영 인력의 IT 숙련도"**. 게시판 활성도가 높으면 그누보드, 운영 편의가 절대적이면 아임웹.

## 7. 디자인 방향 (제안)
- **톤**: 단아·정갈, 여백 중심, 과한 장식 배제 (전통과 현대의 균형)
- **컬러**: 먹색/한지톤 베이스 + 단청에서 추출한 포인트 1색 (과채도 지양)
- **타이포**: 본문 가독성 높은 고딕(Pretendard 등), 제목에 명조 계열 혼용 가능
- **모바일 우선** 반응형, 큰 터치 영역, 메인은 "법회·공지"가 즉시 보이게

## 8. 추진 일정 (WBS 개요)

| 단계 | 주요 산출물 | 기간(예시) |
|------|-------------|:---:|
| 1. 기획 | 요구사항 정의서, IA/메뉴구조도, 화면목록 | 2주 |
| 2. 설계 | 와이어프레임, 화면설계서, 콘텐츠 수급 계획 | 2주 |
| 3. 디자인 | 메인/서브 시안, 디자인 가이드 | 2~3주 |
| 4. 구축 | CMS 셋업·퍼블리싱·게시판/캘린더 구현 | 3~4주 |
| 5. 콘텐츠 이관 | 사찰 소개·법문·사진 등록 | 1~2주 |
| 6. 테스트·오픈 | QA, 모바일·접근성 점검, 운영자 교육 | 1주 |

> 운영자 교육과 **콘텐츠 등록 매뉴얼**을 산출물에 반드시 포함 (자체 운영 지속성 확보).

## 9. 자료 조사가 더 필요한 항목 (다음 단계)
1. **벤치마킹**: 유사 규모 포교사찰 사이트 3~5곳 메뉴·기능 분석표
2. **도메인·호스팅**: 도메인 확보 여부, 국내 호스팅 사양
3. **콘텐츠 자산 현황**: 보유 사진/영상/법문 분량, 기존 SNS(밴드·카페·유튜브) 연동 여부
4. **운영 체계**: 콘텐츠 등록 담당자, 게시판 관리 정책
5. **예산 범위**: 1안~3안별 개략 견적 산정

## 10. 즉시 확인이 필요한 결정 사항
- [ ] CMS 방향(그누보드 / 워드프레스 / 아임웹) 1차 선호
- [ ] 신도 회원제(가입형) vs 비회원 열람형
- [ ] 기존 SNS·유튜브 자산 연동 범위
- [ ] 후원 안내를 '계좌 안내'로 둘지, 추후 결제 연동 여지를 남길지
- [ ] 예상 오픈 시점 / 예산 상한

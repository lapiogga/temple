# 포교사찰 홈페이지 구축 기획 V2

> 작성 단계: 기획 확정 직전 / 구축 방식 변경 반영
> 변경 핵심: **외부 상용 CMS 미사용 → 바이브코딩(자체 개발)**, 회원/비회원 혼용, 중창기 메뉴 신설, 후원=계좌안내, **2026년 8월 하순 오픈**

---

## 0. V1 → V2 변경 요약

| 구분 | V1 | V2 (변경) |
|------|-----|-----------|
| 구축 방식 | 상용/오픈소스 CMS(그누보드 등) | **자체 개발(바이브코딩)** |
| 콘텐츠 관리 | CMS 기본 관리자 | **관리자 화면 직접 구축 필요(신규 핵심 과업)** |
| 회원 | 회원/비회원 택일 검토 | **회원·비회원 메뉴 혼용 (권한 설계 필수)** |
| 사찰소개 | 인사말/연혁/전각 등 | **'가람 중창기' 별도 메뉴 신설** |
| 후원 | 안내 수준 | **계좌 안내로 확정(당분간), 결제 미연동** |
| 규모 | 미정 | **신도 50~150명, 소규모** |
| 일정 | 단계별(예시) | **2026.08 하순 오픈 역산(약 9주)** |

> **가장 중요한 시사점**: CMS를 쓰지 않으므로 "운영자가 글·사진·일정을 올리는 화면"이 공짜로 따라오지 않습니다. **관리자(운영자) 화면 구축이 별도 과업**으로 일정·공수에 반드시 잡혀야 합니다. 이 부분을 놓치면 오픈 후 "기능은 됐는데 직접 글을 못 올리는" 상황이 생깁니다.

## 1. 프로젝트 개요

| 항목 | 내용 |
|------|------|
| 대상 | 지역 신도 중심 포교사찰 (소규모, 신도 50~150명) |
| 구축 방식 | 바이브코딩 자체 개발, 외부 상용 CMS 미사용 |
| 핵심 목표 | ① 사찰 소개·법회/행사 안내 ② 불교 콘텐츠·커뮤니티(법문·게시판) |
| 회원 정책 | 신도회원용·비회원 열람용 **혼용** (메뉴별 권한 차등) |
| 후원 | 계좌 안내(당분간), 온라인 결제 미연동 |
| 오픈 목표 | **2026년 8월 하순** (착수 기준 약 9주) |

규모가 작고 신도 수가 50~150명 수준이므로, 트래픽·동시접속 부담은 거의 없습니다. 따라서 **고사양 인프라보다 "운영 단순성 + 오픈 일정 준수 + 권한 정확성"**이 설계의 우선순위입니다.

## 2. 회원 / 비회원 권한 설계 (V2 신규·핵심)

혼용 구조이므로 메뉴·기능별 권한을 명확히 표로 고정합니다.

| 메뉴 / 기능 | 비회원 | 신도회원 | 운영자(관리자) |
|------------|:---:|:---:|:---:|
| 홈, 사찰소개, **중창기**, 오시는길 | 열람 | 열람 | 열람·편집 |
| 법회·행사, 캘린더 | 열람 | 열람 | 열람·등록 |
| 공지사항 | 열람 | 열람 | 등록·관리 |
| 법문(공개분) | 열람 | 열람 | 등록 |
| 법문(회원 전용분, 선택) | ✕ | 열람 | 등록 |
| 갤러리(공개 앨범) | 열람 | 열람 | 등록 |
| 갤러리(내부 행사 앨범) | ✕ | 열람 | 등록 |
| 자유게시판 | 열람만 또는 ✕ | 열람·작성 | 관리·삭제 |
| 신행수기 | 열람만 | 열람·작성 | 관리 |
| 묻고답하기(Q&A) | ✕ | 작성·열람 | 답변·관리 |
| 댓글 | ✕ | 작성 | 관리 |
| 후원(계좌) 안내 | 열람 | 열람 | 편집 |
| 마이페이지 | ✕ | 본인정보 | 전체 |
| 회원 승인·관리 | ✕ | ✕ | 전용 |

### 회원 가입·승인 흐름 (소규모 적합형)
```
가입신청(최소 정보) → 운영자 수동 승인 → 회원 활성화
```
- 신도 50~150명 규모에서는 **운영자 승인제**가 스팸·외부인 차단에 가장 효과적입니다.
- 회원 등급은 `비회원 / 신도회원 / 운영자` 3단계로 단순화.
- **권한 검증은 보안 핵심**: 바이브코딩 시 화면에서 메뉴만 숨기는 식(프론트 차단)은 우회 가능하므로, **반드시 서버/DB 레벨(접근 정책)에서 권한을 강제**해야 합니다.

## 3. 정보구조(IA) / 메뉴구조도

`(공개)` = 비회원 열람 가능, `(회원)` = 신도회원 전용

```
홈 (공개)
├─ 사찰 소개
│   ├─ 인사말 (공개)
│   ├─ 연혁 (공개)
│   ├─ 가람 배치·전각 안내 (공개)
│   ├─ ★ 가람 중창기 (공개)            ← V2 신설
│   ├─ 스님 소개 (공개)
│   └─ 오시는 길 (공개)
├─ 법회 · 행사 (공개)
│   ├─ 정기 법회 안내
│   ├─ 행사 캘린더 (월간)
│   └─ 연중 불교 행사
├─ 불교 콘텐츠
│   ├─ 법문 (공개분/회원분 혼용)
│   ├─ 경전·교리 안내 (공개)
│   └─ 불교 입문·예절 (공개)
├─ 소식 · 커뮤니티
│   ├─ 공지사항 (공개)
│   ├─ 사찰 소식 (공개)
│   ├─ 갤러리 (공개앨범/내부앨범 혼용)
│   ├─ 자유게시판 (회원)
│   ├─ 신행수기 (열람 공개 / 작성 회원)
│   └─ 묻고답하기 (회원)
├─ 후원 안내 (공개, 계좌 안내)
└─ [회원] 로그인 / 마이페이지
[관리자] 운영자 전용 콘텐츠·회원 관리 (별도 영역)
```

### '가람 중창기' 메뉴 설계 제안
중창기(重創記)는 단순 게시물보다 **연대기형 스토리 콘텐츠**로 구성하는 것이 사찰 정체성에 효과적입니다.
- 구조: 연도(또는 시기) → 중창 내용 → 당시/현재 사진(전후 비교) → 비고
- 표현: 세로 타임라인 + 사진 갤러리 결합
- 데이터: 항목(연도, 제목, 본문, 사진 다중, 정렬순서)을 갖는 별도 콘텐츠 타입으로 관리

## 5. 기술 스택 / 아키텍처 (CMS 대체안)

바이브코딩 효율(AI 코드 생성 적합도) + 소규모 운영 단순성 + 권한 구현 용이성을 기준으로 한 권고안입니다.

### 권장 스택 (1안)
| 레이어 | 선택 | 이유 |
|--------|------|------|
| 프레임워크 | **Next.js (App Router)** | AI 코드 생성 적합도 최상, 풀스택 일원화 |
| UI | **Tailwind CSS + shadcn/ui** | 빠른 반응형, 일관 디자인 |
| 인증·DB·스토리지 | **Supabase (Auth + Postgres + Storage)** | 회원 인증·사진 저장·**행(Row) 단위 접근정책(RLS)으로 권한 강제** 가능 |
| 배포 | **Vercel** (또는 국내 호스팅) | 소규모 트래픽 무료/저비용 |

> 이 조합은 "회원/비회원 혼용 + 게시판 + 갤러리 + 캘린더 + 관리자"를 가장 적은 코드로 구현할 수 있어 9주 일정에 유리합니다. Supabase의 접근정책(RLS)은 권한을 **DB 레벨에서 강제**하므로 혼용 권한 구조에 특히 잘 맞습니다.

### 대안 (2안 — 데이터 국내 보관 우선)
회원 개인정보의 **국외 이전이 부담**이라면: 국내 클라우드(NCP/가비아 등) + 자체 Postgres + 인증 라이브러리(Auth.js) 구성. 운영 부담은 늘지만 데이터가 국내에 머뭅니다. → **3장의 개인정보 이슈와 함께 결정 필요.**

### 데이터 모델 개요 (초안)
```
members        (id, 이름, 연락처, 권한[비회원/회원/운영자], 승인상태, 가입일)
posts          (id, 게시판유형[공지/자유/신행수기/Q&A], 제목, 본문, 작성자, 공개범위, 작성일)
comments       (id, post_id, 작성자, 본문, 작성일)
events         (id, 제목, 일시, 반복여부, 분류[정기법회/행사], 설명)   ← 캘린더
dharma_talks   (id, 제목, 분류, 본문/영상URL, 공개범위, 등록일)         ← 법문
gallery_albums (id, 앨범명, 공개범위) / gallery_photos (album_id, 이미지)
jungchang      (id, 시기, 제목, 본문, 사진[다중], 정렬순서)             ← 중창기
notices/banner (id, 제목, 노출여부, 노출기간)                          ← 메인 노출
```

## 6. 보안 · 개인정보 · 운영

- **권한 강제**: 프론트 메뉴 숨김만으로 불충분 → 서버/DB 접근정책으로 이중 차단. 회원 전용 데이터가 비회원 API로 노출되지 않는지 **반드시 테스트**.
- **개인정보**: 자체 발주라도 회원 정보를 수집하므로 개인정보보호법 적용 대상. 가입 시 **최소 수집·동의 절차**, 개인정보처리방침 페이지, (국외 호스팅 시) **국외 이전 동의** 문구 필요.
- **스팸/어뷰징**: 운영자 승인제 + 비회원 글쓰기 차단 + 캡차 + 작성 빈도 제한.
- **백업**: DB 자동 백업 + 정기 수동 내보내기(export). 사진은 스토리지 백업.
- **운영 지속성**: 비전문가 운영을 전제로 **관리자 화면을 단순하게**, 그리고 **콘텐츠 등록 매뉴얼**을 산출물에 포함.

## 7. 디자인 방향

- 단아·정갈, 여백 중심, 과한 장식 배제 (전통 + 현대 균형)
- 컬러: 먹색/한지톤 + 단청 추출 포인트 1색(과채도 지양)
- 타이포: 가독성 높은 고딕(Pretendard 등), 제목 명조 혼용 가능
- **모바일 우선**, 큰 글씨·큰 터치 영역 (중·장년 신도 배려)
- 메인 최상단에 **법회 일정 + 공지**가 즉시 보이도록

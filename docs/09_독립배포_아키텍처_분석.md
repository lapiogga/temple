> 상태: **결정 완료(2026-07-28) — Hostinger VPS(KVM2)로 확정**. 실행 가이드: `deploy/HOSTINGER_SETUP.md` + `deploy/bootstrap-hostinger.sh`. VPS 구매·접속수단은 사용자 제공 대기.

## 0. 배경/요건 (사용자 발화 종합)

- **독립성**: kis_quant와 별개의 독립 운영환경.
- **접근/기능**: 인터넷 자유 접속 + 로그인 + 데이터 저장/삭제(홈페이지).
- **도메인**: 나중에 결정 후 연결(지금은 도메인 없이, 나중에 쉽게 붙는 구조).
- **규모/성장**: 이관 대상 게시글 ~200 + 이미지 ~2,000장. 월 +50글 / +150~200장. 2~3년+ 사용, 이후 확장성.
- 판단: **별도 DB 구성 + 대량 이미지 스토리지(NAS/오브젝트) 필요**.

3년 추정: 이미지 ~8,300장(~16GB@2MB), 글 ~2,000건. 5년 ~12,500장(~24GB). DB는 텍스트라 소량, 비용 스윙은 **이미지 스토리지·서빙**과 **컴퓨트 고정비**.

## 1. 현재 상태 (진단)

- 앱: Next.js 14.2.35 App Router, `next start` 롱러닝 서버. iron-session `secure=(NODE_ENV==='production')` → **프로덕션 HTTPS 필수**. 이미지 업로드는 `src/lib/upload.js`가 로컬 `public/uploads`에 저장(대규모엔 부적합).
- 인프라: 이 세션은 EC2 **kq-devbox-dev**(kis_quant 공유 박스, 계정 379312655381, ap-northeast-2)에서 실행 중. temple 앱은 3000포트 수동 구동(systemd 아님), PostgreSQL 16 로컬.
- **인터넷 노출 현재 0** — devbox SG 인바운드 규칙 없음(SSM 접속).
- 신규 인프라 생성 권한: run-instances / allocate-address(EIP) / create-security-group **dry-run 확인됨**. RDS/S3/IAM 생성권한은 실행 전 검증 필요.

### 비용 검증(적대적)에서 나온 교정
- **t3.small(2GB)로 `next build` OOM 위험** → 빌드 시 t3.medium(4GB, +$11/월) 또는 외부 CI 필요. AWS안 실비 +$5~30/월 상향.
- **Supabase Pro는 DB/백엔드만** — SSR 앱 미포함. C의 ‘가성비 최선’은 앱티어 합산 시 A와 근접.
- 서울 컴퓨트 단가 실측 대비 ~5% 낮게 잡힘, 5년 flat egress는 성장 전제와 모순(1TB 초과 시 재과금).
- 숨은비용 후보: NAT Gateway(사설서브넷 채택 시 ~$32+/월), EBS 스냅샷(DR), CloudWatch, RDS 퍼블릭 IPv4.
- **비용 최적화 1순위: EC2+RDS 1년 예약/Savings Plan(약 40%↓)** — 최대 비용동인 직격. + 이미지 WebP 변환(2MB→0.3~0.5MB)으로 스토리지·egress·무료티어 여유 개선.

## 4. 권장안 — A) AWS 3계층 (EC2 + 전용 RDS + S3/CloudFront)

```
[인터넷] --HTTPS443(self-signed→certbot)--> [EIP] EC2 t3.small(nginx→127.0.0.1:3000, systemd)
                                                 |  5432(SG→SG)         | S3 SDK(instance profile)
                                                 v                       v
                                          RDS PostgreSQL           S3 temple-uploads-prod
                                          db.t4g.micro(사설)        (+CloudFront/OAC, 이미지 영속·확장)
```
- 앱(EC2) / 전용DB(RDS) / 이미지(S3) 3계층을 **수명주기·SG·IAM으로 분리**. 기존 `deploy/` 자산(systemd·nginx·backup) 재사용.
- 유일한 코드 변경: `upload.js`의 saveImage/saveAttachment를 `@aws-sdk/client-s3` PutObject로(반환 시그니처 유지 → 호출부 무변경).

### ⚠️ 검증에서 반드시 반영할 교정 (must-fix)
1. **‘분리’ vs ‘진짜 독립’**: 같은 계정(379312655381)이면 IAM·과금·blast-radius를 kis_quant와 공유. 기본 VPC는 격리가 가장 약함. → 최소 **신규 전용 VPC**, 진짜 독립은 **별도 AWS 계정(Organizations)**. (결정사항)
2. **S3 Block Public Access 기본 ON(2023~)** → public-read 런북 무효. **CloudFront + OAC(비공개 버킷)**가 정석.
3. **하드코딩 `/uploads` 경로** — `src/app/page.js`, `src/content/about.js`, `src/lib/site-content.js` + DB `site_content`의 사이트 크롬 이미지가 상대경로. S3 전환 시 별도 처리 안 하면 홈/소개 이미지 깨짐.
4. **DB엔 절대 URL이 아니라 상대 key 저장** + 렌더 시 base URL 조립 → 나중 CloudFront/도메인 전환 때 재작성 재발 방지.
5. **self-signed = 관리자/내부 검증 한정.** 일반 방문자엔 브라우저 경고 + **카카오맵 미작동(IP는 도메인 화이트리스트 불가)** → 정식 공개는 도메인+certbot 이후.
6. 런북 순서: IAM instance profile을 EC2 기동 **전에** 생성(또는 무프로파일 기동 후 associate). 마이그레이션 INSERT는 **sanitize-html 재적용**(XSS 차단).

## 5. 마이그레이션 (200글 + 2000이미지) — 소스 확인이 선결(blocking)

- **[사용자 확인 필요]** 원본 형식: 글=SQL덤프/CSV/JSON/CMS export? 이미지=파일폴더/URL/DB BLOB? 글↔이미지 매핑 키, 대상 테이블(notices/events/게시판/갤러리) 대응.
- 절차: 소스 확정→매핑 설계→DB 이관(파라미터화 INSERT + sanitize 재적용)→이미지 스토리지 sync→본문/cover URL 재작성→표본 UAT→건수 대조. 정형이면 반나절, 비정형(수작업 폴더+엑셀·한글파일명)이면 난이도↑.

## 6. 남은 결정사항 (게이팅)

1. **독립성 수준**: 같은 계정 신규 전용 VPC(실용) vs 별도 AWS 계정(진짜 독립) vs 탈-AWS PaaS(프로바이더 분리).
2. **플랫폼**: A(AWS 3계층) vs B(Render+R2, 저비용·싱가포르) vs C(Supabase 서울+앱티어).
3. **공개 시점/HTTPS**: 지금 EIP+self-signed로 내부검증 후 도메인 확보 시 정식공개 vs 도메인부터 확보 후 정식공개.
4. **이미지 스토리지**: S3+CloudFront(권장, upload.js 리팩터) vs EFS(무리팩터·고비용) vs R2(egress무료).
5. 인스턴스 사이즈(빌드 OOM 대비 t3.medium/CI), 예약 인스턴스 적용, 임시계정·noindex 정리 시점.
6. 마이그레이션 원본 소스 포맷(위 §5).

## 8. Hostinger 이전 vs AWS 유지 — temple 연간 이용료 비교

> kis_quant AWS 비용은 두 안 모두 동일한 상수라 제외. temple 호스팅만 비교. 환율 1,380원/USD, VAT 미포함.
> Hostinger는 shared/Cloud가 PostgreSQL 미지원 → **VPS(KVM2: 2vCPU·8GB·100GB NVMe) 전제**. 8GB RAM이라 t3.small 빌드 OOM 문제는 오히려 사라짐.

### 공정 비교 결론 (적대적 검증 반영)

- "3배 저렴"은 **프로모·VPS만·백업제외·prod단독** best-case를 AWS 예약가(내구성 내재)와 섞은 비대칭 비교.
- **정상가 + 내구성 동등화(갱신+일간백업)**: ₩347,594 vs ₩550,000 = **약 1.6배 저렴**.
- **정직한 dev/prod 2대 격리**: ~₩645K → AWS 예약과 **거의 동률**.
- 즉 공정 격차는 **약 1~1.6배**(3배 아님). Hostinger가 절대 우위인 건 '단일 VPS 겸용+프로모' 최저 시나리오뿐.

### 판단

- **비용 + kis_quant 완전 독립 우선 + 자체운영 감수** → **Hostinger KVM2**(+일간백업+off-VPS 백업). 저인터랙션 콘텐츠형 사찰 사이트라 레이턴시 수용 가능.
